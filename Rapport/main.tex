\subsection{Fonction de raffinement}

\begin{definition}\label{def: refinement function}
  The \emph{Refinement function } is a function
  \[
  R : \mathcal{G} \times \Pi \times V^* \to \Pi
  \]
  
  
  such that, for all  $G \in \mathcal{G},  \pi \in \Pi$ \ and  $\sigma \in V^*$,
  
  \begin{enumerate}
      \item $R(G, \pi, \sigma) \preccurlyeq \pi$.
      \item if  $v \in \sigma$, then \{v\} is a cell of $R(G, \pi, \sigma)$.
      \item for any g $\in S_n$, we have $R(G^g, \pi^g, \sigma^g) = R(G, \pi, \sigma)^g$.
  \end{enumerate}
  \end{definition}

  Ce qui signifie:
  \begin{enumerate}
    \item la fonction de raffinement renvoit un coloring plus fin que $\pi$.
    \item si un vertex($v$) est dans la séquence de vertex($\sigma$), alors il doit être dans une cellule de taille 1 dans le coloring raffiné.
    \item Si nous prenons une permutation de notre graphe, notre colouring, et notre séquence de vertex et que nous appliquons la fonction de raffinement à ces éléments, alors nous allons obtenir le même résultat que si nous appliquions la fonction de raffinement à notre graphe, notre coloring, et notre séquence de vertex, et que nous prenions ensuite la même permutation du résultat.
  \end{enumerate}

\subsection{Target Cell Selection}

\begin{definition}\label{def: target cell function}
  The \emph{Target cell selector function} is a function  
  \[
  T : \mathcal{G} \times \Pi \times V^* \to 2^V
  \]
  
  such that, for all  $G \in \mathcal{G},  \pi \in \Pi$ \ and  $\sigma \in V^*$
  
  \begin{enumerate} 
      \item if $R(G, \pi_0, \sigma)$ is discrete, then $T(G, \pi_0, \sigma)$ = \cancel{0}.
      \item if $R(G, \pi_0, \sigma)$ is not discrete, then $T(G, \pi_0,\sigma)$ is a non-singleton cell of $R(G, \pi_0, \sigma)$.
     \item for any g $\in S_n$, we have $T(G^g, \pi^g, \sigma^g) = T(G, \pi, \sigma)^g$.
  \end{enumerate}
  \end{definition}

  Ce qui signifie:
  \begin{enumerate}
    \item Si la fonction de raffinement renvoie une partition discrète(une feuille de notre search tree), alors \emph{Target cell selector function} ne doit pas renvoyer de cellule. $\rightarrow$ vide.
    \item Si la fonction de raffinement renvoie une partition non-discrète(un node de notre search tree), alors \emph{Target cell selector function} renvoye une cellul de cette partition qui n'a pas qu'un seul élément.
    \item Si nous prenons une permutation de notre graphe, notre colouring, et notre séquence de vertex et que nous appliquons \emph{Target cell selector function} à ces éléments, alors nous allons obtenir le même résultat que si nous appliquions \emph{Target cell selector function} à notre graphe, notre coloring, et notre séquence de vertex, et que nous prenions ensuite la même permutation du résultat.
  \end{enumerate}

\subsection{Search Tree construction}

Now that all the formal definitions of the tree have been established, we can define the search tree $\mathcal{T}(G, \pi_0)$, which depends on an initial coloured graph $(G, \pi_0)$. All the nodes of the tree are elements of $V^*$. This search tree has some characteristics to keep in mind:

\begin{itemize}
    \item The root of $\mathcal{T}(G, \pi_0)$ is the empty sequence ().
    \item if $\sigma$ is a node of $\mathcal{T}(G, \pi_0)$, let W = $T(G, \pi_0, \sigma)$. Then the children of $\pi$ are $\{\sigma\mid\mid w: w\in W\}$.
    \item a node $\sigma$ of $\mathcal{T}(G, \pi_0)$ is a leaf iff $R(G, \pi_0, \sigma)$ is discrete.
    \item for any node $\sigma$ of $\mathcal{T}(G, \pi_0)$, define $\mathcal{T}(G, \pi_0, \sigma)$ to be the subtree of $\mathcal{T}(G, \pi_0)$ consisting of $\sigma$ and all its descendants.
    
\end{itemize}

\subsection{Node Invariant}

\begin{definition}\label{def: node variant}
  Let $\Omega$ be some totally ordered set. A \emph{Node invariant} is a function
  \[\phi : \mathcal{G} \times \Pi \times V^* \to \Omega\]

  Such that, for any $\pi_0 \in \Pi$, $G \in \mathcal{G}$ and distinct $\sigma, \sigma' \in \mathcal{T}(G, \pi_0)$.

The function $\phi$ has a few properties to take into account:

  \begin{enumerate}
      \item if $|\sigma| = |\sigma'|$ and $\phi(G,\pi_0, \sigma) < \phi(G,\pi_0, \sigma')$,\\
      then for every leaf $\sigma_1 \in \mathcal{T}(G,\pi_0, \sigma)$ and leaf $\sigma_1' \in \mathcal{T}(G,\pi_0, \sigma')$ we have $\phi(G,\pi_0, \sigma_1) < \phi(G,\pi_0, \sigma_2)$.
      \item if $\pi = R(G,\pi_0, \sigma)$ and $\pi' = R(G,\pi_0, \sigma')$ are discrete,\\
      then $\phi(G,\pi_0, \sigma) = \phi(G,\pi_0, \sigma') \Leftrightarrow G^\pi = G^{\pi'}$ (equality relation).
      \item for any $g \in S_n$, we have $\phi(G^g,\pi_0^g, \sigma^g) = \phi(G,\pi_0, \sigma)$.
      \item Leaves $\sigma, \sigma'$ are \textit{equivalent} if  $\phi(G,\pi_0, \sigma) = \phi(G,\pi_0, \sigma')$. This is the case, if there is a unique $g \in Aut(G, \pi_0)$ such that $\sigma^g  = \sigma'$, with $g = R(G,\pi_0, \sigma')R(G,\pi_0, \sigma)^{-1}$. \rodolphe{Je pense que je vais retirer ça parce que je préfère parler de tout ce qui est groupe d'automorphisme dans la section prévue pour, t'en penses quoi ?}
  \end{enumerate}
\end{definition}

Ce qui signifie:
\begin{enumerate}
  \item Si deux séquences de vertex sont égaux ( $|\sigma| = |\sigma'|$) et que $\phi(G,\pi_0, \sigma) < \phi(G,\pi_0, \sigma')$, Alors cette inégalité se propage à toutes les feuilles descendantes. Aucune feuille descendante de $\sigma$ ne peut être plus grande que n'importe quelle feuille descendante de $\sigma'$.
  \item Si nous avons 2 colourings égaux alors, leur invariant sont égaux si et seulement si ils produisent exactement le même canonical labelling ; Leur appliquer la permutation associé à leur colouring produira exactement le même graphe.
  \item Si nous prenons une permutation de notre graphe, notre colouring, et notre séquence de vertex et que nous appliquons \emph{Node invariant} à ces éléments, c'est équivalent à appliquer \emph{Node invariant} à notre graphe, notre coloring, et notre séquence de vertex, de base.
\end{enumerate}

We can define the canonical form:

\phi^*(G,\pi_0)= \max\ \{\phi(G,\pi_0, \sigma): \sigma \text{ is a leaf of } \mathcal{T}(G,\pi_0)\} ,

In order to ensure that the properties of the \hyperref[def: refinement function]{refinement function} defined in the search tree are respected, we must implement an algorithm that outputs a colouring that is equal to (or finer) than the original colouring. To this end, we rely on a theorem: for every colouring $\pi$, there exists a unique (up to cell ordering) coarsest equitable colouring $\pi'$ such that $\pi' \preccurlyeq \pi$.

Pour créer notre fonction de rafinement, nous aurons besoin de 2 fonctions : Une fonction qui va rafiner un colouring pour que ça devienne un colouring équitable, et une fonction d'individualisation.

  The function \emph{$F(G ,\pi , \alpha )$} is our refinement algorithm (implemented in a label-invariant manner).

  \State \textbf{Data:} $\pi$ is the input colouring and $\alpha$ is a sequence of some cells of $\pi$
  \State \textbf{Result:} the final value of $\pi$ is the output colouring(equitable)

Now we can define a refinement function. For a sequence of vertices $v_1 , v_2 ,\ldots,$ define
\begin{itemize}
    \item $R(G, \pi_0, ()) = F(G, \pi_0,\text{ a list of all the cells of } \pi_0)$  
    \item $R(G, \pi_0, (v_1)) = F(G, I((R(G,\pi_0, ()), v_1), \{v_1\}))$

The algorithm satisfies the required properties of a refinement function and performs well in practice. However, the refinement step is the most computationally expensive part of the algorithm, which is why special care must be taken in its implementation.


\subsubsection{Implementation Target Cell Selector}

\rodolphe{Même chose ici, c'est un peu du copier coller du papier de mckay, je laisse ça comme ça, ou alors je rajoute un peu de sel avec ?}

For the implementation of the \hyperref[def: target cell function]{target cell selection function} in the construction of the search tree, several strategies can be adopted. Choosing the right target cell at each step is important because it influences the shape and depth of the tree, and therefore the overall performance of the search.

In the original version of \Naut, McKay recommended selecting the first smallest non-singleton cell, as it increases the chance that the selected cell is part of an orbit of the group that stabilizes the current sequence~\cite{mckay1981practical}. However, later studies showed that in certain cases, it is better to simply select the first non-singleton cell, regardless of its size~\cite{kirk1985efficiency}.

As a result, \Naut now supports two strategies for target cell selection that we can choose:

\begin{enumerate}
\item Always select the first smallest non-singleton cell.
\item Select the first cell that is joined in a non-trivial way to the largest number of other cells, where a non-trivial join means the number of edges between two cells is strictly between 0 and the maximum possible.
\end{enumerate}


Dans notre implémentation, nous n'utiliserons que la première stratégie.
